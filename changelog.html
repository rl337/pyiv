Changelog

User-facing changes to pyiv, in Keep a Changelog order. Install with pip install pyiv. Unreleased main is pip install git+https://github.com/rl337/pyiv.git.

Unreleased

Added

  • binder.bind(...).to(...).for_package_present(distribution) / for_package_absent(distribution) — select a binding when an optional distribution is installed (any version) or missing. Sugar for for_package_version(distribution, "*") / "!" (PACKAGE_PRESENT / PACKAGE_ABSENT). Pair them for an explicit both-sides choice, or use for_package_present plus an unconditional fallback. Documented with doctests and guide examples alongside other version-conditioned bindings.

1.1.0 - 2026-10-18

Added

  • Use-case stdlib injectable surfaces catalog (docs/inspiration/stdlib-injectable-surfaces.md).

  • pyiv.files — MountFilesystem, ZipFilesystem, TarFilesystem, MappingFilesystem; RealFilesystem(root=…) chroot; compatibility re-export via pyiv.filesystem.

  • pyiv.time — consolidates Clock / DateTimeService (legacy modules re-export).

  • pyiv.process — Environment, ProcessRunner, Argv (+ memory doubles).

  • pyiv.log — Logger / LoggerFactory / LogSetup / LogOptions, CLI helpers, Command add_logging_args / configure_logging_from_args.

  • pyiv.entropy and pyiv.hashing injectable Real/Synthetic surfaces.

  • HttpClientOptions frozen options bag for HTTP clients (Settings-friendly without a pydantic dependency).

  • Agent skill / rule for public types (public-types): knobs as frozen dataclasses; services as Protocol/ABC; no soft pydantic imports.

  • Customer-facing agent skills under agent-skills/ (use-pyiv, pyiv-testing, pyiv.mdc) plus guide :doc:guide/agent-skills with GitHub raw links on main. Maintainer requirement: keep them in sync when public APIs/doubles change.

Changed

  • Named / Matched are frozen dataclasses (eq/hash still ignore Named.default).

  • RecordedRequest, StreamReply, and console TerminalEvent hierarchy are frozen dataclasses.

  • Homepage / testing guide describe use-case stdlib doubles (files, time, log, process, …).

1.0.0 - 2026-10-16

Added

  • :mod:pyiv.http — injectable HttpClient / AsyncHttpClient with typed HttpResponse, streaming, and HttpError / HttpTimeoutError / HttpStatusError. Stdlib UrllibHttpClient / AsyncUrllibHttpClient plus MemoryHttpClient test doubles.

  • Guide page “Migrating from 0.x to 1.x”.

  • pyiv-common RequestsHttpClient implementing HttpClient (RequestsClient remains an alias).

  • Version-conditioned bindings on the fluent Binder: for_version, for_package_version, and for_python_version.

  • :mod:pyiv.version — VersionSource / VersionParser protocols, named parser registry (PEP440 default), InvalidVersion / InvalidSpecifier, injectable PythonVersionProvider (SysPythonVersionProvider / FixedPythonVersionProvider), PackageVersionSource, MapVersionSource, and candidate records.

  • :mod:pyiv.pep440 — public PEP 440 engine and Pep440VersionParser (raises subclasses of InvalidVersion).

  • Guide page “Version-conditioned bindings” for env-stable selection, custom domains, and fallback rules.

Removed

  • pyiv.network (NetworkClient, HTTPClient, HTTPSClient) and ChainType.NETWORK_CLIENT. Use :mod:pyiv.http instead (see the 0.x→1.x migration guide).

0.4.3 - 2026-10-13

Added

  • Injector.catalog_keys(value_type) lists map-multibind catalog ids without constructing plugins (CLI / docs over DI-owned catalogs).

  • Injector.named_keys(binding_type) lists Named qualifiers bound for a type without constructing.

  • Config.contribute_map / contribute_map_entries with on_conflict="replace"|"error"|"keep" for explicit catalog merges.

  • ReflectionConfig.register_module(..., as_multibind=..., key_attr=...) opt-in path that accumulates discoveries into map/set/list multibinds instead of last-wins unqualified register.

  • Guide page “Catalogs without registries” (facade pattern, host contrib, reflection into catalogs).

  • Project logo in the documentation sidebar (RTD left nav header).

  • Documentation site favicon.

0.4.2 - 2026-09-27

Added

  • Constructor injection via Annotated[T, Named(...)] / Annotated[T, Matched(...)], including Optional[T] (None only when there is no candidate; ambiguity still errors) and Annotated[Provider[T], Named|Matched] for lazy qualified lookup.

  • InjectorProvider accepts a Key as well as a bare type.

Notes

  • Annotated Named/Matched applies to constructor (and callable factory) parameters only. inject_members / field injection still resolve bare types; use inject(Key(...)) for qualified field wiring.

  • Matched remains inject-only (not valid on register_key / bind_key).

0.4.1 - 2026-09-27

Added

  • Named accepts a string or list/tuple of tags (normalized to a set); Named("json") == Named(["json"]).

  • Named(..., default=True) marks the preferred binding for bare inject(Type) and for Matched tie-breaks (at most one per type).

  • Matched(required=..., prefer=...) inject-only qualifier: required tags must match, then maximize prefer overlap, then default=True.

  • Bare inject(Type) falls back to Named bindings when no unqualified registration exists (default, sole candidate, or ambiguous error).

Changed

  • Duplicate identical Named tag sets for the same type raise at registration (no silent last-wins). install / merge with replace still overwrites the same tag set.

  • Ambiguous Named/Matched resolution raises CreationError with ambiguous=True; Optional[T] does not treat that as a missing binding.

0.4.0 - 2026-09-25

Added

  • pyiv-common extra package (pip install pyiv-common or pip install pyiv[common]): YAMLSerDe (PyYAML) and RequestsClient (requests). Core pyiv stays stdlib-only.

  • Module composition: Config.install / Binder.install (last install wins).

  • PrivateConfig with expose(), and Injector.create_child() for hierarchical injectors.

  • MapMultibinder / Config.map_multibinder for Dict[K, V] injection.

  • override(base).with_(overrides) for test/prod binding overlays.

  • Stage.DEVELOPMENT / Stage.PRODUCTION with eager singleton warmup.

  • require_explicit_bindings() to disable JIT construction.

  • CreationError with dependency path and circular-dependency detection.

  • Untargeted binder.bind(Concrete) self-bindings; bind_key registers qualified keys; inject Injector by type annotation.

Changed

  • YAMLSerDe moved from core to pyiv-common. from pyiv.serde import YAMLSerDe still works if the extra is installed.

  • Missing bindings and injection failures raise CreationError (with path) instead of bare ValueError / TypeError at the injector boundary.

  • Constructor deps that are concrete types are just-in-time constructed when explicit bindings are not required (transitive JIT).

  • Public class docstrings now state why each type exists and include runnable usage examples (doctest-backed) across core DI and test doubles.
