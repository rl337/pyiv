pyiv.files

Use-case package for injectable filesystem surfaces.

Groups path I/O, mounts, and archive-as-tree adapters under one purpose — not a mirror of os / io / pathlib module names.

What Problem Does This Solve?

File APIs are spread across the stdlib and hard to mock without residue. Inject Filesystem and bind RealFilesystem, MemoryFilesystem, MountFilesystem, or archive-backed trees.

Real-World Use Cases: - Unit tests with MemoryFilesystem (no disk) - Mount a fake /proc via MappingFilesystem + MountFilesystem - Read assets from zip/tar with the same consumer API

Architecture:

  • Filesystem / RealFilesystem / MemoryFilesystem

  • MountFilesystem / MountPoint

  • ZipFilesystem / TarFilesystem

  • MappingFilesystem (dict-backed virtual tree adapter)

Example

>>> from pyiv.files import MemoryFilesystem, MountFilesystem, MappingFilesystem
>>> root = MemoryFilesystem()
>>> root.write_text("/app/config.txt", "x=1")
>>> fs = MountFilesystem(root)
>>> fs.mount("/proc", MappingFilesystem({"uptime": "0.1"}))
>>> fs.read_text("/app/config.txt")
'x=1'
>>> fs.read_text("/proc/uptime")
'0.1'

class pyiv.files.MappingFilesystem(data: Mapping[str, str | bytes] | None = None)[source]

Bases: Filesystem

Expose a string→bytes (or str) mapping as a flat file tree under /.

Why this exists: Pattern for external adapters (DB row as /proc file) without putting SQL in core. Mount under MountFilesystem.

Example

>>> from pyiv.files import MappingFilesystem, MountFilesystem, MemoryFilesystem
>>> proc = MappingFilesystem({"uptime": "1.0", "version": "pyiv"})
>>> fs = MountFilesystem(MemoryFilesystem())
>>> fs.mount("/proc", proc)
>>> fs.read_text("/proc/uptime")
'1.0'

class pyiv.files.MemoryFilesystem[source]

Bases: Filesystem

In-memory filesystem for testing.

Use this whenever code under test needs file I/O but must not touch the real disk. Paths live in a dict-backed store, so tests stay fast and isolated.

Example

>>> from pyiv.files import MemoryFilesystem
>>> fs = MemoryFilesystem()
>>> fs.write_text("/notes/a.txt", "alpha")
>>> fs.mkdir("/notes/sub", parents=True, exist_ok=True)
>>> fs.exists("/notes/a.txt")
True
>>> fs.read_text("/notes/a.txt")
'alpha'

class pyiv.files.MountFilesystem(root: Filesystem | None = None)[source]

Bases: Filesystem

Path-prefix router over nested Filesystem instances.

Why this exists: Expose virtual trees (fake /proc, zip mounts, etc.) beside a real or memory root without monkeypatching open.

Example

>>> from pyiv.files import MemoryFilesystem, MountFilesystem
>>> root = MemoryFilesystem()
>>> root.write_text("/data/a.txt", "a")
>>> proc = MemoryFilesystem()
>>> proc.write_text("/status", "ok")
>>> fs = MountFilesystem(root)
>>> fs.mount("/proc", proc)
>>> fs.read_text("/data/a.txt")
'a'
>>> fs.read_text("/proc/status")
'ok'

class pyiv.files.RealFilesystem(root: str | Path | None = None)[source]

Bases: Filesystem

Real filesystem implementation using the standard library.

Use this in production when you need actual disk I/O. Prefer MemoryFilesystem in unit tests so examples and CI never write into the working tree. Optional root= chroots all paths under a sandbox.

Why this exists: Production Filesystem that performs real disk I/O.

Example

>>> import tempfile
>>> from pathlib import Path
>>> from pyiv.files import RealFilesystem
>>> fs = RealFilesystem()
>>> with tempfile.TemporaryDirectory() as d:
...     p = Path(d) / "hello.txt"
...     fs.write_text(p, "hi")
...     fs.read_text(p)
'hi'

class pyiv.files.TarFilesystem(source: str | Path | bytes)[source]

Bases: Filesystem

Treat a tar archive as a read-oriented Filesystem tree.

Why this exists: Same consumer API as disk/memory/zip for bundled trees.

Example

>>> import io, tarfile
>>> from pyiv.files import TarFilesystem
>>> buf = io.BytesIO()
>>> with tarfile.open(fileobj=buf, mode="w") as tf:
...     info = tarfile.TarInfo(name="a.txt")
...     data = b"x"
...     info.size = len(data)
...     tf.addfile(info, io.BytesIO(data))
>>> fs = TarFilesystem(buf.getvalue())
>>> fs.read_text("/a.txt")
'x'

class pyiv.files.ZipFilesystem(source: str | Path | bytes, *, mode: Literal['r', 'w', 'x', 'a'] = 'r')[source]

Bases: Filesystem

Treat a ZIP archive as a Filesystem tree (read; write when writable).

Why this exists: Apps that read config or assets from a zip should inject the same Filesystem API as disk/memory, including under MountFilesystem.

Example

>>> import io, zipfile
>>> from pyiv.files import ZipFilesystem
>>> buf = io.BytesIO()
>>> with zipfile.ZipFile(buf, "w") as zf:
...     zf.writestr("hello.txt", "hi")
>>> fs = ZipFilesystem(buf.getvalue())
>>> fs.read_text("/hello.txt")
'hi'
