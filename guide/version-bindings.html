Version-conditioned bindings

Select among several implementations of the same interface based on a named version domain — the running Python interpreter, an installed distribution, or any host-defined domain (OS release, wire protocol, …).

See pyiv.version for the full API (sources, parsers, candidates) and pyiv.pep440 for the built-in PEP 440 engine. This page is the how-to.

Fluent API

for_python_version and for_package_version are convenience adapters over for_version. They use the named parser \"PEP440\" (Pep440VersionParser).

Interpreter version is read through an injectable PythonVersionProvider. Production defaults to SysPythonVersionProvider. Tests bind FixedPythonVersionProvider so the same graph can be checked under many Python versions:

from pyiv import Config, get_injector
from pyiv.version import FixedPythonVersionProvider, PythonVersionProvider

class Runner:
    kind = "base"

class LegacyRunner(Runner):
    kind = "legacy"

class ModernRunner(Runner):
    kind = "modern"

class RunnerConfig(Config):
    def configure(self):
        binder = self.get_binder()
        # Omit in production — for_python_version binds SysPythonVersionProvider.
        binder.bind(PythonVersionProvider).to_instance(
            FixedPythonVersionProvider("3.10.12")
        )
        binder.bind(Runner).to(LegacyRunner).for_python_version("<3.11")
        binder.bind(Runner).to(ModernRunner).for_python_version(">=3.11")

inj = get_injector(RunnerConfig)
assert inj.inject(Runner).kind == "legacy"
assert inj.inject(PythonVersionProvider).get_version() == "3.10.12"

Custom domains and named parsers

Register a VersionSource for the domain. Register a custom VersionParser under a name when versions are not PEP 440 (for example an OS release string), then point the domain at that name. Parsers raise InvalidVersion (or a subclass) on bad input.

from pyiv import Config, get_injector
from pyiv.version import InvalidVersion, MapVersionSource

class FsTool:
    name = "base"

class AlpineFs(FsTool):
    name = "alpine"

class AlpineVersionParser:
    def is_version_compatible(self, version, specifier):
        if not specifier.startswith(">="):
            raise InvalidVersion(f"unsupported specifier: {specifier!r}")
        return self._tuple(version) >= self._tuple(specifier[2:])

    def is_version_less(self, a, b):
        return self._tuple(a) < self._tuple(b)

    def is_version_greater(self, a, b):
        return self._tuple(a) > self._tuple(b)

    def _tuple(self, s):
        return tuple(int(p) for p in s.split("."))

class OsConfig(Config):
    def configure(self):
        binder = self.get_binder()
        binder.version_parser("alpine-release", AlpineVersionParser())
        binder.version_source("alpine", MapVersionSource({"alpine": "3.19.0"}))
        binder.use_version_parser("alpine", "alpine-release")
        binder.bind(FsTool).to(AlpineFs).for_version("alpine", ">=3.18")

assert get_injector(OsConfig).inject(FsTool).name == "alpine"

Selection rules

  • Candidates accumulate across install / override (they do not last-wins overwrite each other).

  • Selection runs once at injector construction (environment-stable).

  • Exactly one matching candidate wins; overlapping matches raise CreationError (ambiguous).

  • Zero matches: an unconditional binding for the same type is used as a fallback. Register the fallback after the version-conditioned binds so .to(...) does not overwrite it before for_version retracts the conditional registration.

  • Missing distribution / absent version is a distinct diagnostic (not a silent wrong pick).

Mixing with other bindings

Version candidates live in a separate store from ordinary register / bind(...).to(...) registrations. At injector construction pyiv selects among candidates, then materializes the winner into the ordinary stores (or leaves an existing unconditional binding alone as fallback). The rules below are locked by tests/test_version_binding_mixtures.py.

Match vs fallback

  1. If exactly one candidate matches the environment, that binding is used even when an unconditional binding for the same type also exists.

  2. If zero candidates match and an unconditional binding exists, that unconditional binding is the fallback.

  3. If zero candidates match and there is no unconditional binding, construction raises CreationError.

  4. If two or more candidates match, construction raises an ambiguous CreationError — an unconditional fallback does not break the tie.

Ordering (important)

Register version-conditioned binds first, then the unconditional fallback:

binder.bind(Service).to(Legacy).for_python_version("<3.11")
binder.bind(Service).to(Modern).for_python_version(">=3.11")
binder.bind(Service).to(Fallback)  # after conditionals

Do not put the fallback first. bind(Service).to(Fallback) followed by bind(Service).to(Modern).for_python_version(...) loses Fallback: .to(Modern) last-wins into the ordinary registration map, then for_version retracts that registration into the candidate list, leaving no unconditional binding. The same footgun applies if you self.register(Service, Fallback) before a version-conditioned .to(...).for_*.

Config.register after the version candidates works as a fallback, same as a trailing bind(...).to(...).

Providers, instances, and scopes

  • .to_provider(...) / .to_instance(...) may appear before for_version / for_python_version / for_package_version; the winning candidate keeps that target shape.

  • .in_scope(...) on a version-conditioned chain applies to that candidate. A scoped unconditional fallback is only used when no candidate matches.

  • Unrelated types are unaffected: version selection for Service does not clear or change bindings for Other.

install and override

  • install extends the candidate list (and merges version sources / named parsers). Hosts can add more for_* alternatives or a trailing unconditional fallback.

  • override(base).with_(test) also extends candidates. Unconditional bindings still last-wins: a test module’s bind(Service).to(Fake) replaces the base fallback when no version candidate matches.

  • for_python_version does not eagerly bind SysPythonVersionProvider during configure. A default Sys binding is installed only after merge, and only if no PythonVersionProvider is already present. That way a base FixedPythonVersionProvider survives an override module that only adds more for_python_version candidates.

  • At selection time, every PythonVersionSource is rebound to the merged config so it sees the final PythonVersionProvider (not a submodule’s empty graph).

Package versions

for_package_version(distribution, specifier) reads importlib.metadata.version(distribution). Pass the distribution name (as on PyPI), which may differ from the import package name. Tests should register a MapVersionSource for package:<distribution> (see package_version_domain()) instead of installing multiple package versions.
